# dsh-alexlib

AlexLib 書庫的 DeepSeek Harness 工具。**零執行期依賴**（只用 Node 內建的 `node:sqlite`）。

## 它解決什麼

AlexLib 是 **840 個 OCR markdown（1.08 GB）** 彙整成的統一書庫，但它們是**路徑很多、內容重複**的：
840 個檔案只有 368 本真正不同的書。這個外掛把書庫變成可查的：

| | |
|---|---|
| 檔案 | 840 |
| **唯一書（檔名主幹分組）** | **368** |
| chunk | 279,819 |
| 索引 | `AlexLib/index.db`（約 1.36 GB） |

## 五個工具

| 工具 | 做什麼 |
|---|---|
| `alexlib_search` | 搜尋（中文片語級、簡繁自動統一） |
| `alexlib_doc` | 讀某一本書的內容，可翻頁看 chunk |
| `alexlib_list` | 列出書（依來源或標題篩選） |
| `alexlib_stats` | 索引狀態 |
| `alexlib_reindex` | 更新索引（跳過已索引的） |

## 中文怎麼切：重疊二字組

連續漢字切成重疊的二字組，拉丁與數字照原樣：

```
認知作戰  ->  认知 知作 作战      （先逐字轉簡體）
```

查詢也走同一條路，而且**每一個二字組都必須命中**。這讓查詢變成**片語級**：

```
認知作戰  ->  认知 AND 知作 AND 作战
```

**這修掉了一個實際的假陽性。** GAS 知識庫（jieba 分詞 + AND）對「認知作戰」回傳的是
《指揮控制系統仿真》裡講睡眠與認知能力的一段——因為它把查詢拆成 `认知` + `作战`，
任何同時出現這兩個詞的段落都算命中。這裡要求 `知作` 也必須命中，那段就出局了。

實測（368 本書）：

| 查詢 | 結果 |
|---|---|
| `認知作戰` / `认知作战` | **0 命中** —— 書庫裡真的沒有這個主題 |
| `情报分析` | 《指挥控制系统仿真》§5.7 通信侦察仿真 |
| `复杂系统` | 《系统科学概论》§第5章 复杂系统及其特征 |
| `anycast` | *Understanding Distributed Systems* §18.2 |

### 簡繁必須統一

`认知作战` 與 `認知作戰` 必須查到同一批東西，否則等於半個書庫查不到。
`t2s.json` 是 **4,221 個字對**，由本機的 opencc 逐字產生（只做單字對應——片語級轉換需要上下文，對切詞沒有幫助）。

⚠️ 產生與使用這一端有個坑：Python 的 `len()` 數的是**碼點**，JS 的 `str[i]` 數的是**碼元**。
`U+F900–FAFF` 的相容漢字會轉成非 BMP 字元，逐碼元索引會從那裡整個錯位。
所以讀表時必須 `Array.from()`（見 `t2s()` 的註解）。

## 三層去重

| 層 | 鍵 | 合併了什麼 |
|---|---|---|
| 1 | 檔案的 sha256 | 位元組完全相同的副本（840 → 516） |
| 2 | **清洗後文字**的 sha256 | 同一次 OCR 的不同輸出 |
| 3 | **檔名主幹**（去掉 `_by_PaddleOCR*`、`.clean`） | 同一本書被 OCR 兩次（516 → **368**） |

第 3 層留**檔案最大**的那一份當代表（OCR 最完整），其餘路徑全部記在 `all_paths`，
所以 `alexlib_doc` 還是看得到所有副本位置。

## 其他設計決定

- **自己一份索引**，不共用 GAS 的 `kb/gas.db`——書庫的索引跟著書庫走。
- **清洗 HTML**：PaddleOCR 會把版面標記一起吐出來。不清的話索引被 `div style text align` 塞滿。
- **chunk 有硬上限**（`CHUNK_MAX = 2200`）：`build_kb.py` 在「單一段落大於上限」時不切，
  做出過 13 MB 的單一 chunk。這裡一律硬切。
- **FTS5 `detail=none, columnsize=0`**：我們用二字組 AND 而不是 FTS 的片語查詢，不需要位置資訊。

## 用法

```bash
node index.js --build            # 建索引（約 45 秒）
node index.js --build --force    # 整批重建（會先清空）
node index.js --stats
npm test
```

環境變數：`ALEXLIB_ROOT`（不設時由**使用者家目錄**推導成 `~/source/repos/AlexLib`，不寫死任何使用者名稱）、`ALEXLIB_DB`。

## 已知限制

1. **不做跨語言檢索**：中文查詢不會命中英文書（`共识算法` 查不到 *Understanding Distributed Systems* 的 consensus algorithm）。
2. **第 3 層去重靠檔名**：同一本書如果檔名不同（例如 `...2nd Edition.pdf` 與 `...2nd Edition (1).pdf`），仍是兩筆。
3. **沒有向量檢索**：純 BM25。
